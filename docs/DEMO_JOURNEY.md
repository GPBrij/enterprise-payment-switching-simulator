# Demonstration Journey

1. Present the architecture overview and publication boundary.
2. Submit a normal synthetic transaction and show routing, authorization and journaling.
3. Submit controlled decline scenarios and explain response codes at a conceptual level.
4. Demonstrate fraud controls using synthetic test cards and values.
5. Create a settlement batch from approved, unsettled transactions.
6. Compare batch totals with issuer positions to demonstrate reconciliation.
7. Open the operations dashboard to show transaction KPIs, approval outcomes, issuer volumes, fraud evidence and settlement reporting.
8. Show Git tags to demonstrate release governance and traceability.

## Demonstration safeguards

- Use synthetic test data only.
- Do not enter real cardholder or banking data.
- Do not expose environment files, secrets, credentials or internal source walkthroughs.
- Keep the presentation focused on capabilities, controls, architecture and outcomes.
